# Quickstart — Kuro Core v0.1.0

> Local-first zero-trust security gate and multi-scanner engine for developers.

---

## What is Kuro Core?

**Kuro Core** is a standalone, single-binary CLI and local Git pre-push interception proxy. It runs directly on your workstation without requiring databases, NATS brokers, or cloud accounts.

- **Zero-Dependency Local Analysis**: Coordinates Gitleaks, Semgrep, Trivy, and Checkov directly using Docker or Podman.
- **Fail-Closed Git Proxy**: Intercepts `git push` on `localhost:8000` to block secrets and vulnerabilities before code leaves your computer.
- **Interactive TUI & Auto-Remediation**: Built-in Bubbletea terminal interface and automated secret remediation (`kuro fix`).
- **Cyber Deception**: Plant and verify honeypot canary tokens (`kuro canary`).

## Installation & Build

### 1. Build from source
```bash
git clone https://github.com/Haiagari/kuro-core.git
cd kuro-core
make build
```
The compiled standalone binary is placed in `bin/kuro`.

### 2. Optional: Install to system PATH
```bash
sudo make install
```

---

## Usage

### 1. Check your environment
```bash
./bin/kuro doctor
```

### 2. Scan a local repository
```bash
# Interactive TUI scan
./bin/kuro scan /path/to/your/project

# Structured JSON output for local scripts
./bin/kuro scan /path/to/your/project --json

# Full git history scanning
./bin/kuro scan /path/to/your/project --history
```

### 3. Interactive Auto-Fix & Secret Extraction
```bash
# Preview auto-remediation without touching files
./bin/kuro fix /path/to/your/project --dry-run

# Automatically extract detected secrets to environment variables
./bin/kuro fix /path/to/your/project --auto
```

### 4. Cyber Deception Canary Tokens
```bash
# Generate a fake AWS honeypot credential
./bin/kuro canary generate --type aws --format env

# Verify if a suspicious token was generated by Kuro
./bin/kuro canary verify AKIAIOSFODNN7EXAMPLE
```

### 5. Run System Diagnostics
```bash
./bin/kuro doctor
```

## Pre-Push Protection with Local Git Proxy

Run the lightweight local proxy to block insecure commits automatically.

By default the proxy uses **`SCAN_MODE=local`**: it shells out to `kuro scan --json`, so the `kuro` binary must be on `PATH` (or set `KURO_BIN` to its path). For the Enterprise API path instead, set `SCAN_MODE=api` (also accepts `remote` / `enterprise`) and point `KURO_URL` / `KURO_API_KEY` at your API.

```bash
# Ensure kuro is available (SCAN_MODE=local default)
export PATH="$PWD/bin:$PATH"   # or: export KURO_BIN=$PWD/bin/kuro

# Start proxy (runs on :8000)
cd services/git-proxy && go run .

# Enterprise API mode (optional)
# SCAN_MODE=api KURO_URL=http://api:8080 KURO_API_KEY=... go run .
```

Point your repository remote to the local proxy:
```bash
git remote add proxy http://localhost:8000/my-org/my-project.git
git push proxy main
```

If secrets or critical vulnerabilities are introduced, the push is immediately rejected at the TCP layer. Run `kuro doctor` if the proxy cannot find scanners or the CLI.
